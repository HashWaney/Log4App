# Log4App 使用说明

## 一、背景

设备或 App 出现问题时，现场日志往往分散在采集端设备上，人工导出和传给排查人员比较繁琐。Log4App 在电脑上启动一个局域网日志接收服务，让已接入协议的采集端 App 扫码取得电脑地址，再把日志包直接上传到电脑本地，方便现场查看和后续排查。

Log4App 是**电脑端接收工具**，采集端 App 是**日志来源**。两端通过局域网 HTTP 通信，默认使用 TCP `9090` 端口。完整的 [业务流程图和交互时序](LOG4APP_FLOW.md) 可单独查看。

## 二、主要功能

| 功能 | 说明 |
| --- | --- |
| 服务与二维码 | 启动后自动开启日志服务，检测电脑的局域网 IPv4，并生成包含服务地址的二维码；地址变化时界面会刷新。 |
| 设备登记 | 采集端 App 扫码后调用设备 Ping，桌面端显示设备名称、ID、版本和最后通信时间；最近 90 秒有通信显示“已连接”。 |
| 日志接收 | 接收采集端上传的日志包，单次上传上限默认 500 MB；服务端保存原始文件，不在界面中解析日志内容。 |
| 录屏反馈 | 通过独立接口接收 MP4 录屏，保存在独立目录，不改变原日志上传接口和日志文件。 |
| 本地查看 | 分别显示本次日志、录屏上传次数和最近 50 条记录；可一键打开日志或录屏目录。 |
| 服务控制 | 可在界面上停止或重新启动接收服务，也可复制服务器地址。 |

## 三、支持平台

下表是项目**当前构建配置**提供的电脑端产物：

| 电脑系统 | 架构 | 安装或运行形式 |
| --- | --- | --- |
| Windows 10/11 | x64 | 安装程序 `.exe`、便携版 `.zip` |
| macOS | ARM64 | `.dmg`，内含 Log4App 应用 |
| Linux | x64、ARM64 | Debian/Ubuntu 系 `.deb`、便携版 `.tar.gz` |

采集端已有 [Android 接入说明](ANDROID_INTEGRATION.md)。服务协议也允许其他平台的 App 接入，但客户端需要自行实现扫码解析、设备 Ping 和日志上传；本仓库不提供其他平台的采集端安装包。

## 四、使用前准备

1. 在电脑上安装或启动 Log4App，在采集端设备上使用已接入 Log4App 协议的 App。
2. 确认电脑与采集端可以通过局域网互访；同一 Wi-Fi 名称并不必然代表网络互通。若使用虚拟机，还需确认虚拟机的网络模式允许采集端访问其局域网 IP。
3. 允许采集端访问电脑的 TCP `9090` 端口。Windows 安装程序会添加“专用网络”入站规则；macOS 如弹出入站连接提示，请选择允许；Linux 按现场防火墙规则放行。
4. 仅在可信的局域网内使用。当前接口是 HTTP，未提供账号登录或传输加密。

## 五、操作步骤

### 1. 启动电脑端

- **Windows**：运行安装版的 Log4App，或解压便携版后运行 `log4app.exe`。
- **macOS**：打开 `.dmg` 中的 Log4App 应用。
- **Linux Debian/Ubuntu 系**：安装与系统架构一致的 `.deb` 后，从应用菜单启动，或在终端执行 `log4app`。

应用启动后会自动尝试开启服务。确认首页显示“日志服务运行中”、本机局域网 IP 和二维码。如果服务已停止，点击“启动服务”。如果未检测到局域网 IP，二维码区域会显示等待提示。

### 2. 用采集端 App 扫码

在采集端 App 的日志上传入口扫描电脑端二维码。二维码内是服务地址等信息的 JSON，不是可直接在浏览器打开的普通网址。采集端应先调用设备 Ping；成功后，电脑端“已登记设备”区域会出现该设备。

如果长时间没有新的设备通信，设备会从“已连接”变为“最近连接”。这表示超过 90 秒没有收到该设备的 Ping 或上传请求，不代表已保存的日志被删除。

### 3. 上传并查找日志

在采集端 App 发起日志上传。上传成功后，电脑端会更新本次上传统计、设备最后上传信息与“最近日志”列表；界面通常在约 2 秒内刷新。点击“打开日志目录”可查看完整文件。

日志默认保存在应用文档目录下的 `Log4AppLogs`，按以下层级整理；实际绝对路径以首页显示的“日志目录”为准：

```text
Log4AppLogs/
└── <设备 ID>/
    └── <日期>/
        └── <时间戳>_<App 版本>_<原始文件名>
```

应用重启后，已保存的日志仍在本地；“已登记设备”和“本次上传”统计会重新开始。

### 4. 上传并查找录屏反馈

扫码连接成功后，采集端可点击“录屏反馈”并选择一个 MP4 文件。上传成功后，电脑端会在“最近录屏反馈”中显示该文件；点击条目可用系统默认播放器打开。

录屏默认保存在与日志目录同级的 `Log4AppVideos`，同样按设备 ID 和日期整理。录屏和日志使用不同接口及目录，互不混放。

## 六、常见问题

| 现象 | 检查方式 |
| --- | --- |
| 没有二维码 | 查看服务是否运行、电脑是否检测到局域网 IPv4；网络地址变化后等待界面刷新。 |
| 扫码后没有设备 | 确认采集端调用的是 `POST /api/device/ping` 且带有 `deviceId`；仅调用旧的 `GET /api/log/ping` 不会登记设备。 |
| App 无法连接 | 检查二维码中的电脑 IP、两端网络互通情况，以及电脑防火墙的 TCP `9090` 入站规则。 |
| 上传失败 | 检查服务状态、`deviceId` 和文件是否随请求发送；录屏必须是 MP4，单次上传不得超过默认 500 MB。 |
| 看不到较早日志 | 首页只展示最近 50 条，点击“打开日志目录”查看本地全部文件。 |

供接入开发和接口联调使用的字段、响应格式见 [Server API](SERVER_API.md)。
